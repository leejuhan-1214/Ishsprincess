# RE:ACTION · 빈자리에 남긴 약속

이름을 직접 입력하고 시작하는 한국어 브라우저 비주얼노벨. 인천과학고등학교 **1학년 1반**으로 온 전학생이 여덟 반 친구와 사이언스 페어를 준비하며 각자의 약속을 쌓아 간다.

[게임 플레이](https://leejuhan-1214.github.io/Ishsprincess/) · [소스 저장소](https://github.com/leejuhan-1214/Ishsprincess)

등장인물·사건·학교 생활·행사·시설 배치는 허구다. 실제 학생이나 학교의 운영을 재현하지 않는다. 교내 이야기는 비성적인 청소년 로맨스로 구성한다.

## 현재 게임의 기준

활성 진입점은 `src/main.tsx` → **`src/RomanceGame.tsx`**다. 이야기는 `romanceTypes.ts`, `engine/romance.ts`, `data/romanceStory.ts`, `data/romanceHangouts.ts`, `data/romanceMystery.ts`를 사용한다. 이번 버전의 장면 일러스트와 활동은 각각 `data/romanceArt.ts`, `data/romanceActivities.ts`에서 연결한다.

이전 `App.tsx`와 기존 엔진·스토리·일러스트는 보관되어 있지만 새 게임의 진행 경로는 아니다. 이전 버전의 34개 엔딩, 42개 신규 컷씬, 히든 다자 루트, 매 장 재판 등이 새 버전에 모두 연결되어 있다는 뜻이 아니다. [CUTSCENES.md](CUTSCENES.md), [ASSETS.md](ASSETS.md)와 기존 아트 프롬프트 문서는 과거 제작 자산의 참고 자료이며, 현재 플레이 기능은 이 README와 활성 코드로 확인한다.

| 영역 | 새 버전의 구현 |

### 모바일 플레이

별도 설치 없이 위 게임 링크를 휴대폰 브라우저에서 열면 된다. 대사창과 선택지를 터치해 진행하고, 지도 상단의 장소 선택창으로 이동할 수 있다. 자료 선택·확대, 모든 미니게임, 저장·불러오기도 화면 버튼으로 조작한다.

- 세로 화면은 그림 위·대사 아래, 낮은 가로 화면은 그림 왼쪽·대사 오른쪽 배치다.
- 주소창·키보드에 따른 화면 높이 변화와 노치·홈 표시줄 여백을 반영한다. 긴 목록과 자료는 해당 패널 안에서 스크롤한다.
- 주요 터치 버튼은 최소 44px, 이름 입력과 모바일 선택창은 16px 글씨를 사용한다. 화면 확대는 차단하지 않는다.
- 저장은 현재 기기·브라우저에 보관된다. PC와 휴대폰 사이에 자동 동기화되지는 않는다.

## 다섯 장의 흐름

| 장 | 제목 | 중심 흐름 |
| --- | --- | --- |
| 1 | 삼십 분 늦게 온 봄 | 첫 만남과 약속. 다른 시각의 쪽지를 발견하지만 아직 인쇄 실수로 생각한다. |
| 2 | 같이 틀린 박자 | 같이 연습하며 가까워진다. 예약까지 어긋나자 친구들이 앞선 일과 비슷하다고 먼저 말한다. |
| 3 | 서로 다른 곳에서 | 집중 관계의 데이트와 작은 비밀. 세 장소로 갈라진 공지를 함께 비교하며 같은 결과가 반복됨을 알아챈다. |
| 4 | 내일이 오기 전에 | 페어 전야의 약속. 승인본이 있었는데도 구버전이 배포된 순서를 확인하고 단순 실수만으로는 설명하기 어렵다고 느낀다. |
| 5 | 빈자리에 남긴 약속 | 공연 중지 요청과 사실과 다른 주장이 도착한다. 교사와 당사자가 함께 확인한 뒤 무대와 각자의 약속으로 돌아간다. |

각 장에는 세 개의 메인 구간이 있다. 1~4장에서는 인물에게 범인 역할을 번갈아 맡기거나 재판을 반복하지 않는다. 친구들의 관찰이 대화 속에서 단계적으로 달라진다. 읽지 않은 사건이나 뒤의 진행을 제목 화면·기록·관계 설명에서 예고하지 않으며, 자료 하나로 고의나 범인을 확정하지 않는다.

2장 끝에는 일곱 히로인 중 한 명, 준연과의 친구 동행, 또는 아직 한 사람으로 정하지 않는 선택이 가능하다. 이후 메인 장면은 선택한 관계를 반영한다. 마지막 사건을 해결해도 축제와 관계의 마무리를 생략하지 않는다.

날짜는 D−64부터 페어 당일의 주요 시점을 따라 이동한다. 모든 날짜를 하루씩 시뮬레이션하는 게임은 아니다. 조건에 맞는 후일담은 페어 이후 네 주에 걸쳐 이어진다.

기본 구성은 **메인 15개**, **자유 만남 80개(8명 × 5장 × 첫 만남·후속 만남)**, **수습 후일담 4개**, 그리고 집중 관계·판결·관계 수치에 따른 마지막 장면이다. 각 만남은 세 선택지와 각각의 대화 응답을 갖는다. 후속 만남 40개는 공통 재방문 문장을 이름만 바꿔 반복하지 않고 별도의 제목·대사·선택지·응답을 갖는다. 같은 인물의 같은 장 이야기를 두 번 마치면 더는 재활용 만남을 열거나 행동을 소비하지 않는다.

메인 선택에는 장면별로 작성한 결과가 있으며, 3장 집중 관계의 CG 데이트에는 일곱 명 각각의 선택과 이후 회상이 있다. 1장에서 해당 첫 만남을 이미 읽었다면 3장에서는 같은 순간을 다시 처음처럼 소개하지 않고, 함께 들었던 노래·그렸던 그림·찾았던 게임 화면의 다음 이야기로 이어진다. 기존 5장 개정 기획 PDF의 큰 줄기와 준연의 조건은 유지하며, 이번 CG·활동·대화 개편의 실제 연결 상태는 이 문서와 활성 코드를 기준으로 한다.

## 시작과 조작

이름을 입력하고 **시작하기**를 누른다. 기본 이름은 없으며 앞뒤 공백을 제외한 1~12자를 사용한다. 저장을 이어 읽으려면 제목 화면의 **이어하기**를 선택한다.

| 조작 | 동작 |
| --- | --- |
| 대사창 클릭·탭, `Space`, `Enter` | 현재 문장 전체 표시 → 다음 대사 |
| 선택지 클릭·탭, 화면 번호의 숫자키 | 현재 표시된 선택지 결정 |
| `자동` | 대사를 자동으로 넘기며 선택지에서는 정지 |
| `읽은 대사` | 이미 읽은 대사만 넘기기 |
| `기록` | 최근 대화와 선택 기록 확인 |
| `기억` / `수첩` | 직접 확보한 자료 확인 |
| `관계` | 각 친구의 호감·신뢰와 집중 관계 확인 |
| `저장` | 수동 슬롯에 현재 진행 저장 |
| `Esc` | 열린 자료·창을 닫거나 메뉴 열기 |

선택지에는 정답·보상 예고 태그를 붙이지 않는다. 회차 시드와 장면을 기준으로 순서를 섞으므로 좋은 선택이 항상 맨 위에 있지 않다. 같은 저장에서 같은 장면으로 돌아오면 순서를 유지하며 숫자키도 화면 순서를 따른다.

설정에서는 대사 속도, 배경음, 음량을 바꾼다. 배경음은 처음에는 꺼져 있다. 전체화면은 브라우저가 지원할 때 사용할 수 있으며 모바일에서는 화면 버튼으로 모든 필수 진행을 할 수 있다. 새 버전에는 이전 `Ctrl` 연속 스킵이나 선택 후 수치 알림 설정이 연결되어 있지 않다.

### 방과 후 지도와 활동

16개 장소는 각각 다른 배경을 사용한다. 기존 교실·화학실·밴드실·댄스실·컴퓨터실·천문대 배경에, 정문·정원·식당·도서관·미디어실·미술실·강당·옥상·산책로·복도 전용 배경 10장을 추가했다. 실내 복도와 야외 산책로도 구분한다. 지도 미리보기와 대화 배경은 `locationImage()`를 함께 사용한다.

새 배경은 내장 `image_gen`으로 제작했으며 `public/assets/locations/`에 저장한다. [프롬프트](art-prompts/locations-v4.json)와 [선택 출력 기록](art-prompts/locations-v4-selected.json)을 함께 보관한다.

메인 구간을 마치면 지도에서 장소를 선택한다. 인물 위치는 회차·장·현재 시간과 만남 진행에 따라 달라진다. 아직 확인하지 않은 자료의 대화 상대는 그 현장에서 만날 수 있도록 배치한다.

- 지도에서 인물을 만나면 **이야기와 선택 응답부터** 읽는다. 활동을 먼저 시키고 뒤늦게 상황을 설명하지 않는다.
- 각 장의 **첫 만남**이 끝나면 그 상황에 맞는 활동 초대를 받는다. 수락하거나 대화만 하고 마칠 수 있다.
- **후속 만남**은 새 대화로 이어지며 추가 미니게임을 끼워 넣지 않는다. 같은 장의 세 번째 만남은 열리지 않는다.
- 한 지도 구간에서 만남은 **2회**이며 같은 인물은 그 구간에 한 번만 만날 수 있다.
- 자료 확인은 만남 횟수를 소모하지 않는다. 남은 만남이 0이어도 모든 필수 기록을 찾을 수 있다.
- 만남 횟수를 모두 사용할 의무는 없다. 다만 현재 구간에서 열린 주요 자료 확인을 마치지 않으면 다음 구간으로 넘어갈 수 없다. 주요 대화와 선택 응답도 끝까지 진행해야 한다.

방과 후 데이터는 여덟 인물의 장별 첫 만남과 후속 만남을 별도로 작성한다. 이전 선택, 현재 장의 진행, 관계에 맞는 반응을 사용하며 선택 결과는 대화로 보여 준다. 지도에서 만난 장소와 실제 대화 장소가 다를 때는 이동을 설명하고 배경·장소 표기도 바꾼다.

활동은 **8명 × 5장, 총 40개의 초대와 과제**다. 매번 같은 문제 목록에서 세 라운드를 뽑는 방식이 아니라, 그날 대화에서 제안한 **한 가지 일**을 함께 한다.

| 장르 | 함께 하는 일 |
| --- | --- |
| 소리 섞기 | 세 음색의 비율과 분위기를 고른다. 취향을 고르는 활동이며 음향 미리보기 없이도 완료할 수 있다. |
| 동작·리듬 맞추기 | 손동작이나 차례를 따라 한다. 기본은 시간 제한 없이 진행하며 박자 도전은 선택 사항이다. |
| 종이 구성하기 | 엽서·관찰 카드·연습 계획의 조각을 배치한다. 필요한 항목을 지키면서 개인 취향을 넣을 수 있다. |
| 작은 디버깅 | 여러 입력을 직접 시험하고 기대 결과와 비교한 뒤 잘못된 조건을 고친다. |
| 별그림·동선 잇기 | 함께 고른 지점을 거쳐 길을 잇는다. 천문 지식을 외우는 시험이나 실제 시설 안전 지도가 아니다. |
| 가방 꾸리기 | 제한된 칸에 약속한 필수 물건과 원하는 여분을 넣는다. |

활동은 재시도하거나 **그만하고 이야기로 돌아갈 수 있다**. 초대를 거절하거나 완료하지 않고 나가도 호감·신뢰를 깎지 않고, 보상도 받지 않는다. 완료 보상은 해당 활동에 한 번만 반영된다. 활동 성공은 메인 이야기·자료 확보·재판의 필수 조건이 아니다. 대화 선택에는 호감이나 신뢰가 낮아지는 반응도 있으며, 모든 장면의 세 선택이 같은 정답·오답 구성을 따르지는 않는다.

### 함께한 순간 · 새 장면 일러스트

일곱 히로인에게 하나씩, **새로운 가로형 PNG CG 7장**을 연결했다. 기존 인물 사진을 크게 고정하는 대신 이야기의 해당 대사에서 장면 그림으로 전환하며, 관련 대화와 선택 응답이 끝나면 일반 대화 화면으로 돌아온다. 정지 일러스트이며 동영상이나 애니메이션은 아니다.

### 기록

자료는 수첩에서 한꺼번에 받지 않는다. 지도에 표시된 장소를 방문해 확인 대화를 끝까지 읽으면 기록된다. 앞선 자료를 봐야 이어지는 확인도 있다. 미발견 자료의 이름·총수·후반 활용 시점은 수첩에 미리 노출하지 않는다.

자료마다 공개 범위와 **이 기록만으로 알 수 없는 것**을 적었다. 표시 이름·접근 권한·담당 업무 하나를 개인의 행위나 의도에 대한 확정 증거로 취급하지 않는다. 기록 이미지는 한글로 작성된 가상 SVG 문서이며 **2배 확대**와 **이미지 저장**을 지원한다.

자료 8개를 모았다는 이유만으로 즉시 재판에 들어가지는 않는다. 5장 첫 이야기에서 공연 중지 요청을 듣고, 친구들이 받은 안내를 꺼내어 함께 교실로 이동한다. 원본과 말을 맞춰 보자는 제안에 서로 동의하면서 대화가 학급재판으로 이어진다. 별도의 개회 안내·재판 시작 메뉴는 두지 않는다. 학생의 학교생활을 재판하거나 공개 망신을 주는 행사가 아니라 당사자와 교사가 함께하는 비공개 사실 확인이다. 준연의 범행과 공연 중지 요청 작성은 기록을 대조한 뒤 본인의 설명으로 드러나며, 시작 화면이나 앞선 만남에서 미리 인정하지 않는다.

재판에서는 모순된 발언을 고르고, 리볼버형 약실에 기록을 **말 탄환**으로 장전한 뒤 **선택한 발언에 증거 제시**를 누른다. 약실을 직접 고르거나 좌우 버튼·약실 내부 방향키로 이동할 수 있다. 올바르게 대응하면 **논파** 연출이 나타난다. 이후 근거 설명을 읽고 직접 **논증 이어가기**를 눌러 진행한다.

세 번의 증거 논증 뒤에는 네 사건을 시간순으로 놓는다. 마지막에는 상처받은 마음과 타인에게 준 피해의 책임을 구분하는 대화가 이어진다. 오답은 자료를 다시 살펴보고 재시도하는 방식이며, 시간 제한·강제 패배 횟수·모든 히로인의 호감 일괄 차감은 없다.

## 관계와 후일담 — 스포일러

<details>
<summary>결말과 관계 조건 보기 (스포일러)</summary>

준연이 다른 사람들의 약속과 공지를 바꾼 사실은 여러 기록과 본인의 구체적인 설명을 교차 확인하여 드러난다. 외로움이나 실제 서운했던 일을 인정하는 것과 고의적인 훼방의 책임을 면제하는 것은 다르게 다룬다. 다른 일곱 인물에게 돌아가며 범인 역할을 맡기지 않는다.

최종 판결의 갈림길은 다음 **두 가지**다.

- **A · 프로젝트에서 내보내고 개인적인 관계를 끝낸다.** 준연의 프로젝트 권한과 추가 만남을 종료한다. 학생 투표로 학교에서 퇴학시키는 결말이 아니다. 학교 생활과 별도 수습은 교사가 담당하며 다른 히로인과의 약속은 계속된다.
- **B · 책임을 다하는 조건으로 다시 기회를 준다.** 제한된 역할과 확인 절차 아래 정정·수습을 진행하고 네 주의 후일담을 읽는다. 다른 인물의 용서까지 주인공이 대신 결정하지 않는다.

준연의 호감은 1~4장과 5장의 결정 전까지 **0~70**으로 제한한다. A에서는 상한 70을 유지하고 추가 동행을 닫는다. B를 고르면 **상한만 100**으로 바뀐다. 현재 호감이 63이면 63, 70이면 70 그대로이며 과거의 초과분을 되돌려 주지 않는다. 신뢰는 별도 수치다.

준연과의 연애는 용서의 자동 보상이 아니다. 조건은 B 선택, 수습 후일담 완료, **1~4장 중 서로 다른 두 장 이상에서 준연과 동행**, 호감 85 이상, 신뢰 70 이상이다. 다른 히로인에 집중하지 않은 상태(준연 또는 미선택)이고 확정한 다른 연애가 없어야 한다. 자격을 갖추면 마지막에 제안이 열리며 서로 연애 의사를 선택해야 연인으로 이어진다. 우정으로 마무리하는 것도 가능하며 별도의 세 번째 재판 판결은 아니다.

기존에 선택한 히로인은 준연으로 자동 교체되지 않는다. A/B 판결은 다른 일곱 명의 호감·신뢰를 일괄 올리거나 내리는 선택이 아니다.

일반 히로인의 마지막 연애 선택은 해당 인물을 집중 관계로 정하고 호감 60·신뢰 45 이상일 때 제시된다. 조건을 충족해도 친구로 남거나 당분간 각자의 시간을 보내는 선택이 가능하다.

</details>

## 저장과 버전 전환

저장은 브라우저 `localStorage`를 사용한다. 계정·서버 저장·기기 간 동기화는 없다. 개발 서버, 공개 사이트, 다른 브라우저와 기기의 저장 공간은 서로 다르다. 사이트 데이터를 삭제하면 세이브와 수집 기록도 사라진다.

- 로맨스 진행 저장: `reaction-romance-v2:auto`, `reaction-romance-v2:1` ~ `reaction-romance-v2:10`
- 전역 기록: `reaction-romance-v2:read`, `reaction-romance-v2:endings`, `reaction-romance-v2:settings`, `reaction-romance-v2:art`
- 이전 엔진 저장: `reaction-v1:` 영역을 삭제하거나 덮어쓰지 않는다. 현재 게임에서는 그 진행을 자동 변환하거나 불러오지 않는다.

화면의 버전은 **Story Edition 3.0**이지만 저장 키와 상태의 버전 번호는 기존 로맨스 v2를 유지한다. 유효한 기존 로맨스 세이브는 **이어서 하기**에서 불러올 수 있다. 새 대사와 장면을 앞에서부터 보려면 **새로운 이야기 시작**을 선택한다. 수동 슬롯을 덮어쓸 때는 같은 버튼을 한 번 더 눌러 확인한다. 제목 화면으로 돌아가도 마지막 자동 저장은 유지된다.

대사와 선택 응답, 재판 피드백, 재구성 중 놓아 둔 순서는 저장된다. 미니게임 안의 세부 조작은 저장하지 않으므로 불러오면 그 활동을 다시 시작한다. 완료한 활동의 관계 효과는 중복 지급하지 않는다. 이전 로맨스 버전에서 **대화 전에 시작했던 미니게임**을 저장한 경우에는, 해당 만남의 대화 첫머리로 복원해 상황과 선택을 먼저 읽도록 한다. 기존 관계와 이미 얻은 기록을 이 때문에 초기화하지 않는다.

세이브에는 이름, 장·구간, 현재 대사, 관계, 선택 기억, 현장에서 모은 자료, 만남 횟수, 회차 시드, 재판과 후일담 진행이 담긴다. 불러올 때 구조와 진행 조건을 검사하며 준연의 상한도 다시 적용한다. 대화 기록은 최근 800줄까지 보관한다. **기억의 서랍**에는 이번 로맨스 진행에서 감상한 CG와 도달한 결말이 표시되며, 구버전 일러스트 갤러리 전체를 보여 주는 화면은 아니다.

## 개발과 검증

기존 코드 회귀 검사와 Story Edition 3.0의 진행·관계·자료·만남 반복 방지·CG 연결·활동 검사를 함께 실행한다. 테스트 개수와 통과 여부는 배포 시 실제 실행 결과로 확인한다. 자동 검사는 모든 대사를 사람이 읽거나 모든 기기를 검증했다는 뜻은 아니다.

Node.js **22.18.0 이상**과 pnpm 또는 npm을 사용한다. 저장소의 잠금 파일은 `pnpm-lock.yaml`이다.

```bash
git clone https://github.com/leejuhan-1214/Ishsprincess.git
cd Ishsprincess
pnpm install --frozen-lockfile
pnpm dev
```

npm을 사용한다면 `npm install` 후 `npm run dev`로 실행한다. `package-lock.json`이 없는 첫 설치에서 `npm ci`를 사용하지 않는다. 터미널에 표시된 개발 서버 주소를 브라우저로 열며 `file://`로 파일을 직접 실행하지 않는다. 게임 실행에 별도의 서버 계정이나 API 키는 필요하지 않다.

```bash
# 자동 테스트
pnpm test

# TypeScript 검사 + GitHub Pages용 빌드
pnpm build

# 빌드 결과 미리보기
pnpm preview
```

npm에서는 각각 `npm test`, `npm run build`, `npm run preview`를 사용한다.

테스트 러너는 기존 코드의 회귀 검사와 새 로맨스 엔진·자료 검사를 함께 실행한다. 구버전 테스트가 통과했다고 해당 기능이 새 화면에 연결됐다는 뜻은 아니다. 새 버전을 바꿀 때는 최소한 다음을 확인한다.

- 1~4장에서는 재판이 열리지 않고 5장에서만 마지막 재판으로 이어지는가.
- 첫 대화와 필수 기록을 거치지 않고 재판으로 건너뛸 수 없는가. 재판은 개회 메뉴 대신 등장인물의 대화에서 이어지는가.
- 제목·빈 기록·관계 화면에 사건 주체나 후반 시점을 미리 알리는 문구가 없는가.
- 80개의 만남에서 첫 만남과 후속 만남의 제목·본문·선택지가 구별되고, 세 번째 만남이 반복 대사와 보상을 만들지 않는가.
- 인물별 7개 CG의 원본이 존재하고 실제 대사에서 표시되며, 본 그림만 갤러리에서 저장할 수 있는가.
- 첫 만남의 대화 뒤에만 활동을 제안하고, 거절·중도 종료·저장 복원으로 보상을 중복 받을 수 없는가.
- 지도 장소·선행 자료 조건이 맞고 행동 0회와 활동 건너뛰기 상태에서도 모든 자료를 얻을 수 있는가.
- 선택 효과가 한 번만 적용되고 저장·복원 후 선택 순서와 진행이 일관되는가.
- 준연의 상한 70, B 이후 상한 100, 현재 수치 유지, A의 동행 종료가 적용되는가.
- 재판의 오답·정답·순서 재구성 뒤에 다음 장면이 정상적으로 열리는가.
- 수동 저장·자동 저장·이어 읽기, 모바일 대사창, 자료 확대, 키보드 선택과 미니게임을 직접 조작할 수 있는가.

이 문서는 확인하지 않은 최신 테스트 통과 개수나 모든 기기의 수동 플레이 완료를 주장하지 않는다. 배포마다 실제 검사 결과와 모바일 화면을 별도로 확인한다.

## GitHub Pages 배포

`vite.config.ts`는 상대 경로 `base: './'`와 출력 폴더 **`docs/`**를 사용한다. `docs/`는 설명 문서가 아니라 배포용 게임 빌드다.

1. 테스트와 `pnpm build` 또는 `npm run build`를 실행한다.
2. 변경된 소스와 새 `docs/` 결과를 함께 커밋해 `main`에 반영한다.
3. 저장소 Settings → Pages에서 `Deploy from a branch`, 브랜치 `main`, 폴더 `/docs`를 지정한다.
4. Pages 배포가 성공한 뒤 [공개 플레이 주소](https://leejuhan-1214.github.io/Ishsprincess/)에서 실제 동작을 확인한다.

소스만 수정하고 빌드 결과를 갱신하지 않으면 공개 게임은 이전 내용으로 남는다. 다음 빌드에서 생성되는 `docs/`를 직접 고치지 않는다. 저장소의 `.git` URL은 복제 주소이며 게임 플레이 주소가 아니다.

업데이트 직후 이전 화면이 보이면 강력 새로고침을 시도한다. 저장을 유지하려면 사이트 데이터를 지우지 않는다. README의 배포 절차 자체는 현재 배포 성공을 확인했다는 보고가 아니다.

## 현재 범위

- 외부 생성형 AI 채팅과 음성 연기는 없다. 대사에 감정 표기를 사용하지만, 인물의 눈·입을 매번 새로 그린 감정별 얼굴 세트는 아니다. 일반 대화는 공통 인물 원화, 연결된 순간은 새 장면 CG를 사용한다.
- 예전의 별도 개인 루트·히든 다자 확률·엔딩 애니메이션·특전 포토카드 UI는 새 진행에 연결하지 않았다.
- 기본 구성은 메인 15개 구간, 자유 만남 80개, 선택적 활동 40개, 새 CG 7장, B 이후 네 주의 수습과 조건별 마지막 장면이다. 분기 조건 때문에 모든 만남이 한 회차에 열리는 것은 아니다. 이전 버전의 대사·엔딩·CG 수를 새 버전 분량으로 합산하지 않는다.
- 새 CG 7장은 실제 이야기의 해당 순간에 연결되어 있다. 모든 대사·수습·엔딩에 개별 그림을 만들거나 과거 컷씬을 임의 재생하지는 않는다. 증거 발견 장면에는 자료 SVG가 표시된다.
- 실내 복도·계단은 학교 뒤 산책로와 구분한다. 장소별 배경의 실제 연결은 `src/data/characters.ts`에서 확인한다.
- 페이지 바깥을 스크롤해 대사를 찾지 않도록 구성하지만, 긴 기록·관계·저장 목록과 작은 창의 긴 내용은 해당 패널 내부에서 스크롤할 수 있다.
